    Complete feature 035 — OpenAI Agents SDK backend¶

    Status: In progress; T0–T3 complete (4/12 tasks). The T3 sample ran live on Azure OpenAI (E8); remaining live provider evidence for T1, T2, and T3 (OpenAI platform, collector, Ollama) stays with T10. Created: 2026-09-06. Owner: Backend maintainers, with serving, deployment, retrieval, and documentation maintainers for their respective tasks. Baseline: b585e80 plus the uncommitted reconciliation from this session. Requirements: 035 specification and acceptance matrix.

    Objective and observable acceptance criteria¶

    Finish the agreed 035 parity scope and close its outstanding acceptance gaps. An OpenAI or Azure agent must support the declared tools, hooks, handoffs, serving, deployment, and telemetry behavior. Claude behavior and provider-neutral execution contracts must remain intact.

    Completion requires all twelve tasks below, with linked evidence for each acceptance gate. Every functional requirement and success criterion must have a disposition: verified, superseded by a recorded decision, or explicitly deferred with an owner and exit criterion. A missing credential, skipped test, implemented adapter, or checked historical task does not prove acceptance. The original specification contains superseded requirements. This plan does not claim that its deferred sandbox and hardened-profile scope is delivered.

    Canonical records and scope¶

    This file is the active execution checklist for completing 035. The full plan remains the detailed design reference for tasks A–K. The old TODO and reconciliation report retain the audited baseline and historical counts. Do not maintain another parallel completion checklist in those records. Update this plan with implementation decisions, test commands, results, and remaining blockers after each task.

    In scope:

    • Remaining full-parity tasks D, E, G, I, J, K and the partial F4/H1 acceptance work.
    • Baseline acceptance for implemented A, B, C, F and the MVP/SK cleanup gates.
    • Open LiteLLM migration acceptance in its task record, including H-009.
    • Documentation corrections in the documentation plan.
    • Requirement reconciliation, reproducible fixtures, final verification, and archival of completed records.

    Existing deferrals remain separate: P3/Envoy, sandbox mode, computer-use, interactive human approval, MCP-server tool guardrails, modify, prompt-tool execution, and namespace unification. Final Semantic Kernel decommission remains H-008 in the debt tracker. This plan closes the native-backend migration and its inference acceptance. It does not replace the eleven vector-store connectors or remove the SK package. T0 must give each deferred item a durable destination. A deferral must not be labelled implemented.

    Constraints and decisions¶

    • Use BackendSelector and the contracts in src/holodeck/lib/backends/base.py.
    • Preserve current routing: OpenAI/Azure use OpenAI Agents; Anthropic/Ollama use Claude.
    • Keep the openai: namespace and the Azure /openai/v1 Responses mapping established by #338.
    • Use typed boundary adapters and validated Pydantic configuration. Do not bypass known types with Any or getattr.
    • Preserve multimodal execution, evaluation-model overrides, tool events, and GenAI instrumentation.
    • Keep network calls and blocking I/O outside Temporal workflow execution and async event loops respectively.
    • Verify SDK integration points against the installed, locked SDK before implementation. Do not copy obsolete SDK assumptions from the draft spec.
    • Do not change unrelated working-tree edits or add a repository-wide import linter as part of this feature.
    • The user authorized plan creation and T0 contract reconciliation. Future live deployment validation follows the explicit target-authorization rule in Reliability.

    Task checkboxes mean all listed acceptance and verification criteria are satisfied, not just that source code exists. Dependencies require upstream implementation and local gates to be ready. They do not require live gates assigned to T10 to finish first. Record “implementation ready; live acceptance pending” in progress when that distinction applies. T10 evidence then closes the upstream live gates. Proposed new test files are labelled as additions. Other file paths below are repository-relative.

    Verification commands and evidence format¶

    For each Python change, run focused Black, Ruff, MyPy, and relevant pytest tests through uv run. Run pytest with -n auto. Use the existing quality map to select consumers of shared contracts. After model changes, run make schema and make schema-check. At final integration, preserve CI/pre-commit requirements and run:

    uv run pre-commit run --all-files
uv run pytest -n auto --cov --cov-branch --cov-report=xml
make security
make schema-check
make harness-check
uv run mkdocs build --strict

    Keep live service tests separately identifiable. Record skips and unavailable services, rather than treating a green summary as complete live acceptance. Do not rerun broad suites after they pass unless the candidate changes or a new concern warrants it.

    Each task records: commit/configuration identity, changed behavior, command, result/count, artifact reference, and remaining limitation. Do not store credentials or raw sensitive traces in the evidence.
