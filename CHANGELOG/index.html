    Changelog¶

    All notable changes to HoloDeck will be documented in this file.

    The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

    Unreleased¶

    Planned Features¶

    • Deployment Engine: Registry push (holodeck deploy push) and cloud deployment (holodeck deploy run)
    • Plugin System: Pre-built plugin packages for common integrations

    0.8.0 - 2026-11-10¶

    This section also lists the changes that shipped in 0.7.0 and 0.7.1, which had no section of their own.

    Upgrading from 0.7.x¶

    This release removes Semantic Kernel and splits the install into feature extras. Read this list before you upgrade. The same steps with commands are in the upgrade guide.

    1. Check your install extras (BREAKING). pip install holodeck-ai no longer installs DeepEval, anthropic, ollama (new eval extra), nltk, rouge-score, sacrebleu (new nlp extra), optuna (new optimizer extra) or opensearch-py (new opensearch extra). MkDocs Material and Twine left the runtime requirements for the dev extra. The new all extra installs every runtime extra. A test run whose configuration selects a metric without its extra stops before any agent or model call and prints the install command (MissingExtraError); holodeck test optimize and an OpenSearch keyword index do the same. Commands that do not use these features still start. The vector store MissingClientError is now a MissingExtraError with the same attributes.
    You ran Now run
    pip install holodeck-ai and use DeepEval or NLP metrics pip install "holodeck-ai[eval,nlp]"
    pip install holodeck-ai and use holodeck test optimize pip install "holodeck-ai[optimizer]" (add eval,nlp for its metrics)
    pip install holodeck-ai and use an OpenSearch keyword index pip install "holodeck-ai[opensearch]"
    pip install holodeck-ai and want everything as before pip install "holodeck-ai[all]"
    1. Update retired metric names (BREAKING). Azure AI evaluation and azure-ai-evaluation are removed (042 T18); DeepEval metrics replace them. An agent.yaml that names a retired metric fails when the configuration loads, before any agent or model call, and the error names the replacement. HoloDeck does not translate old configuration, and scores are not equivalent: re-run the suite and set new thresholds. Stored runs that used these metrics still open in the dashboard. See Removed Azure AI metrics.
    Removed metric: Use instead (DeepEval)
    groundedness type: rag, metric_type: faithfulness
    relevance type: rag, metric_type: answer_relevancy
    coherence type: geval with coherence criteria
    fluency type: geval with fluency criteria
    similarity type: geval with evaluation_params: [actual_output, expected_output]
    safety type: geval with safety criteria
    1. Update retired vector store providers (BREAKING). The faiss, sql-server and azure-cosmos-mongo providers had no install extra, sample or live test and could not run from a documented install. An agent.yaml or global config.yaml that names one fails at config load with a migration message, before any backend, embedding or agent call. Stored runs that name a retired provider still open in the dashboard. The published agent.schema.json lists only the eight supported providers.
    Removed provider Use instead
    faiss chromadb (embedded, local files) or in-memory
    sql-server postgres (pgvector)
    azure-cosmos-mongo azure-cosmos-nosql

    1. Check your vector collections. Plain text chunking changed (BREAKING for stored chunks): TextChunker is now a HoloDeck splitter (tiktoken cl100k_base) instead of Semantic Kernel's characters/4 estimate. chunk_size is a hard per-chunk token limit, chunk_overlap tokens are repeated at the start of the next chunk, and splits prefer paragraph, line, sentence, then word boundaries. chunk_overlap >= chunk_size and a non-default separator_list now raise ValueError; an unset vectorstore chunk_overlap defaults to 50 capped at a quarter of chunk_size, and an explicit 0 is honored. Collections now record the pipeline that wrote them in a companion holodeck_manifest collection. A tool refuses writes to a collection written by a different pipeline and lists the inputs that differ; searches still work. Collections created before this release stay usable and are marked legacy, with their old chunks until re-ingested. Run holodeck vectorstore inspect for a read-only report, then holodeck vectorstore migrate to rebuild into a new collection (resumable and verified; the old collection is kept until prune). See the vector stores guide.

    2. Download the METEOR data once. METEOR no longer downloads NLTK data on first use. When wordnet, punkt_tab or omw-1.4 is missing it raises NLPMetricsError that names the resource and the command python -m nltk.downloader wordnet punkt_tab omw-1.4. Run that command once on each machine that scores METEOR.

    3. A missing vector store client is an error. A vectorstore or hierarchical_document tool no longer falls back to in-memory storage when the provider's client library is missing or the provider name is retired. The tool fails with the install command or the migration text. A failure while the store adapter is created still falls back to memory. A client that connects on first use (Qdrant, for example) raises its connection error; it does not fall back.

    4. ChromaDB scores changed. Chroma returned a cosine distance that was used as the similarity score, so semantic results ranked worst-first and min_similarity_score kept the least similar chunks. Scores are now 1 - distance, and the best match ranks first. Review any threshold you tuned against the old ranking.

    5. MCP 2 is allowed. The mcp range is >=1.30.0,<3 (was <2) and the lock moves mcp 1.30.0 to 2.3.0. claude-agent-sdk 0.2.179 and openai-agents 0.24 accept it, and both backends pass the offline smoke run and make verify-live on 2.3.0.

    6. Rebuild deployment images. holodeck deploy build and the base image install an exact HoloDeck version with dependency versions constrained to that release's uv.lock. They no longer use --prerelease. See the Changed section for the options and the build manifest.

    7. Semantic Kernel is removed (BREAKING for Python imports). semantic-kernel is no longer a dependency of any install profile. Every vector store provider runs on a native adapter behind holodeck.lib.retrieval, and embeddings and contextual-retrieval chat run on LiteLLM. Existing Qdrant, Chroma and Postgres collections stay readable and writable: their layout is frozen under tests/fixtures/legacy_layout/ and checked against the native adapters. Removed Python surfaces: the holodeck.lib.vector_store module (QueryResult and StructuredQueryResult now live in holodeck.lib.retrieval), the SK bridge adapter, holodeck.lib.observability.enable_semantic_kernel_telemetry with its SK_OTEL_* constants, and holodeck.lib.keyword_search.get_keyword_search_strategy with its provider-name sets (the adapter's capabilities choose the hybrid strategy). HoloDeck no longer sets the SEMANTICKERNEL_EXPERIMENTAL_GENAI_ENABLE_OTEL_DIAGNOSTICS variables. No agent key named Semantic Kernel remains (the last one, metrics.include_semantic_kernel_metrics, went in 0.7.0). The default of observability.logs.filter_namespaces changes from ["semantic_kernel"] to []. The lock no longer allows pre-releases globally (tool.uv.prerelease is removed), the azure-search-documents cap is relaxed from <12.1 to <13, and the lock goes from 378 to 347 entries at this step (376 to 329 over the whole dependency work).

    Other breaking changes in this release, not part of the dependency work: Python 3.11 or later is required, the tool_filtering agent field is removed, the Claude backend isolates settings by default, and more built-in Claude tools need a declaration. Each has its own entry below.

    Added¶

    • Pipeline fingerprint, ingestion completion marker and holodeck vectorstore. Retrieval collections now record the pipeline that wrote them (embedding provider, model and dimensions, parser and chunker policy and settings, record layout, contextual embeddings) in a companion holodeck_manifest collection; the layout of existing collections is unchanged. A tool refuses writes to a collection written by a different pipeline and lists the inputs that differ; searches still work. Collections created before this release stay usable and are marked legacy. Each ingested source is marked incomplete before its chunks are written and complete after, so an interrupted ingestion is redone on the next start. New commands: holodeck vectorstore inspect (read-only dry run with chunk and token estimates), migrate (rebuild into a new collection, resumable, verified, old collection kept), rollback and prune. See the vector stores guide.
    • Native Weaviate adapter. The weaviate provider runs on the asynchronous weaviate-client 4.x with native vector, BM25 and hybrid search, filtered reads, cursor pagination and source replacement. New weaviate extra (weaviate-client>=4.24,<5, also in vectorstores). The lock adds weaviate-client 4.24.1 and validators 0.36.0 and moves grpcio 1.85.1 to 1.78.2 (the client requires grpcio<1.80). The Semantic Kernel path never worked against a server, so no stored collections change; free-text record IDs are now stored as UUIDv5 with the original in a holodeck_id property, collection names are normalized to Weaviate's rules, and unknown database settings are an error. See the vector stores guide.
    • Native Azure Cosmos DB NoSQL adapter. The azure-cosmos-nosql provider no longer goes through Semantic Kernel's connector, which also needed pymongo to import. New extra azure-cosmos (azure-cosmos>=4.17,<5; the lock adds 4.17.1; also in vectorstores). The container layout is unchanged (partition key /id, float32 cosine embedding policy, same index exclusions). New: HoloDeck picks quantizedFlat above 505 dimensions (SK's flat could not create a container for 1536 dimensions); item IDs with / \ ? # are stored encoded (SK's writes failed on them); writes run concurrently; an existing container with other dimensions or partition key is rejected; unknown database settings are an error. Native hybrid search (ORDER BY RANK RRF) is opt-in with full_text_search: true. Verified on the Linux emulator (all operations except hybrid search) and on a test fake; hybrid search and the Cosmos DB service itself are unverified.
    • Native Azure AI Search adapter. New azure-ai-search extra (azure-search-documents 12.0, azure-identity) and an adapter on the asynchronous clients with vector, keyword and native hybrid search, exact-match filters, key-range enumeration and index creation. hierarchical_document tools now work on Azure AI Search (stale chunks are removed on re-ingestion). The index layout follows what Semantic Kernel created, with differences: record IDs that Azure rejects as keys (paths) are stored Base64-encoded, filterable and searchable are set only where needed, and the key is sortable, so an index created by Semantic Kernel is rejected with a clear error. Entra ID signs in when no api_key is set. Verified against an in-memory fake and the SDK's request shapes on a stub transport; not run against the Azure service yet.
    • OpenAI Agents native backend (Feature #035) — model.provider: openai and azure_openai now run on a first-class backend built directly on the OpenAI Agents SDK (Agent + Runner), replacing the former Semantic Kernel agent path. Verified end-to-end against Azure OpenAI with the financial-assistant sample (hierarchical-document RAG over Qdrant + numeric eval).
    • Tools: Python function tools, plus vectorstore and hierarchical_document RAG tools (reusing the same .search()/embedding layer as the Claude backend; surfaced to the model as {name}_search).
    • MCP: stdio / sse / http transports map to the SDK MCP server classes with ${VAR} env/header substitution and per-server allowed_tools static filtering; transport: websocket is skipped with a warning.
    • Structured output: response_format (JSON-schema dict or file path) drives the SDK output type; strict mode auto-enables when the schema qualifies. Note: OpenAI structured outputs reject oneOf — use anyOf (the same schema works on the Claude backend).
    • Reasoning thinking: populated from reasoning-model summaries when effort is set.
    • openai: config block (sibling of claude:): max_turns, effort (low|medium|high|max; max → SDK xhigh), max_budget_usd (per-session cost cap → BackendBudgetExceededError with partial response), fallback_model (one fallback attempt on 429/5xx after primary retries exhaust), disallowed_tools, permissions, and serve-sizing knobs.
    • Tracing: an OTel-mirroring TracingProcessor reflects SDK spans into the HoloDeck OTel pipeline. HoloDeck owns the SDK's process-global processor list through one router with per-backend policies applied per trace, so mixed OpenAI/Azure agents keep their own upload behaviour in either initialization order. provider: openai retains the platform.openai.com upload alongside the mirror; azure_openai never uploads (also with observability disabled); observability.disable_provider_tracing: true forces mirror-only. trace_include_sensitive_data is tied to observability.traces.capture_content (default off) on every run.
    • Subagents / handoffs: openai.agents.<name> entries become SDK handoff targets (transfer_to_<name>), inheriting the parent's tools and MCP servers unless restricted, with model: inherit or an explicit id (Claude aliases rejected) and the SDK's recommended handoff prefix prepended once unless skip_recommended_prefix: true. Handoffs surface on the existing tool-event stream (start/end/parent_link/subagent_message/thinking) so holodeck chat and AG-UI render them like Claude subagents.
    • Skills: new type: skill tool (inline instructions or a path to a SKILL.md directory; YAML-only allowed_tools) validated at config load and, on this backend, translated into a scoped handoff-target sub-agent. claude.setting_sources is accepted for portability and warns that it is ignored on this backend. A runnable full-capability sample lives in sample/openai-agents-full/.
    • Roadmap (not yet shipped on this backend): YAML hooks, hosted tools, default credential-redaction guardrails, and holodeck serve / holodeck deploy (all fully supported on the Claude backend).

    Changed¶

    • Deployment images are pinned and constrained. holodeck deploy build and the base image install an exact HoloDeck version (holodeck-ai[extras]==X.Y.Z, no --prerelease flag), with dependency versions constrained to that release's uv.lock: the wheel now ships holodeck/deploy/constraints.txt and overrides.txt (make constraints; make constraints-check runs in make verify-fast). The base image build needs HOLODECK_VERSION (an exact release) and scripts/build-base-image.sh needs --version; both pin the Python and uv images by digest, and Dockerfile.local no longer pipes the uv installer to a shell. deploy build builds on holodeck-base:<version> of the version it runs. A development version (not on PyPI) needs --wheel or a matching wheel in ./dist; otherwise the build stops before Docker starts. New deploy build options: --wheel, --base-image, --no-pull.
    • Extras in deployment images are chosen from the agent file. One function (holodeck.deploy.extras.required_extras) maps the agent to extras: openai-agents for OpenAI and Azure OpenAI, the vector store extra from the adapter registry (now including weaviate, azure-ai-search, azure-cosmos), opensearch for an OpenSearch keyword index, otel-prometheus and otel-azmon for those exporters, and claude-otel only when Claude-backend tracing is on (before, every Anthropic agent got it and OpenAI agents got no openai-agents). Serving images never get eval, nlp or optimizer.
    • Native Pinecone adapter on client 10. The pinecone provider no longer goes through Semantic Kernel's connector. The pinecone extra is now pinecone>=10,<11 (was pinecone[asyncio,grpc]~=7.0, a dev build); the lock moves pinecone 7.0.2.dev1 → 10.3.0 and drops pinecone-plugin-interface, protoc-gen-openapiv2 and lz4. The index layout is unchanged (serverless, cosine, record ID as the vector ID, data fields as metadata, one namespace). hierarchical_document tools now work on Pinecone: find uses the client's fetch-by-metadata, and stale chunks are removed on re-ingestion. Changes to know: index names are normalized to Pinecone's rules (documents_dim1536 becomes documents-dim1536, which Pinecone rejected before); unknown database settings are an error instead of being passed to the client; use_grpc is ignored (the async client uses HTTP); record IDs must be ASCII. Verified on Pinecone Local with a test-only control plane and on a fake client; no run against the Pinecone service yet. The Dependabot ignore for Pinecone majors is removed.
    • Retrieval tools use HoloDeck's vector store adapter contract. vectorstore and hierarchical_document tools no longer call Semantic Kernel collections directly; collection names and stored layout are unchanged. A changed file's stale chunks are now removed on re-ingestion. A hierarchical_document tool on a provider without filtered reads fails before ingestion instead of re-ingesting silently; every supported provider has filtered reads, so none hits that error today.
    • ROUGE and METEOR run without Hugging Face evaluate. ROUGEEvaluator calls rouge_score directly and METEOREvaluator calls nltk.translate.meteor_score directly, with the same parameters and scores as before (the frozen golden fixtures pass unchanged). Neither metric fetches a script from the Hub. METEOR no longer downloads NLTK data on first use: when wordnet, punkt_tab or omw-1.4 is missing it raises NLPMetricsError naming the resource and the command python -m nltk.downloader wordnet punkt_tab omw-1.4. nltk and rouge-score are in the new nlp extra. CI downloads and caches the data before the tests, the METEOR tests skip with that command as the reason when it is absent, and the evaluation guide documents the one-time download. evaluate, datasets, pyarrow, dill, multiprocess and xxhash leave the lockfile (345 to 339 packages), and the datasets and pyarrow constraints are removed.
    • markitdown[all] replaced by format extras (042 T20): the dependency is now markitdown[pdf,docx,pptx,xlsx], and openpyxl, pandas, pdfminer.six and python-pptx are declared directly. Ten packages leave the lock: azure-ai-documentintelligence, azure-ai-contentunderstanding, youtube-transcript-api, speechrecognition, pydub, olefile, xlrd, audioop-lts, standard-aifc, standard-chunk. Legacy .xls, audio, YouTube and Outlook conversion are not used by FileProcessor. The lock goes from 339 to 329 packages. The explicit azure-ai-contentunderstanding>=1.2.0b1 constraint that the Semantic Kernel removal added (only markitdown[all] needed that pre-release) is dropped, so the lock holds no pre-release outside packages that ship only pre-releases.
    • Fewer direct dependencies. aiofiles, python-dateutil, absl-py, ml-dtypes, requests and the stale sentry-sdk constraint are no longer declared; nothing in src/ imports them. aiofiles and ml-dtypes leave the lockfile (376 to 374 packages). The remote file download and the MCP registry client now use httpx instead of requests (redirects are followed; timeouts are unchanged). anthropic and ollama stay declared because DeepEval's Anthropic and Ollama judge models need them.
    • Remaining major upgrades. temporalio 1.32 → 1.35 (exact pin), opensearch-py 2.8 → 3.2, dash 3.4 → 4.5 and twine 6.2 → 7.0. twine 6.2 could not read wheels with metadata 2.5, so the release twine check was failing.
    • Faster CLI start. Commands now load only their own modules. Every command used to import the evaluation stack (pandas, DeepEval), Semantic Kernel and the agent SDKs at startup: a first holodeck init in a fresh environment drops from about 25 s to 1 s. holodeck test still loads what it needs. This also fixes subprocess tests that timed out on busy CI runners.
    • DeepEval 4 and ChromaDB 1.5. deepeval 3.8.9 → 4.3.3. It needs posthog 7, which chromadb 1.0.x rejects, so the chromadb extras now allow <1.6 (locked 1.5.9). DeepEval 4 also accepts reasoning-model judges such as gpt-6-luna, which 3.8.9 rejected (it sent temperature: 0). The four ignored chromadb advisories are unchanged by 1.5.9.
    • Azure Container Apps SDK 5. azure-mgmt-appcontainers 4.0 → 5.1. SDK 5 returns provisioning_state as an enum, so deploy and status now report its value (Succeeded) instead of ContainerAppProvisioningState.SUCCEEDED. It also stopped sending activeRevisionsMode, allowInsecure and transport by default; the deployer now sets them explicitly, so the request body matches 4.x.
    • OpenAI stack on openai 3. openai 2.54 → 3.48, openai-agents 0.20 → 0.24 and litellm 1.100 → 1.108, moved together: openai-agents 0.21+ requires openai 3, and litellm allows it from 1.108.
    • Agent runtime upgrade. claude-agent-sdk 0.2.121 → 0.2.179 and openai-agents 0.17.4 → 0.20.0. The openai<2.45 cap is lifted. openai-agents 0.21 and later need openai 3, which the next entry covers.
    • Claude tool search is off by default. Claude Code 0.2.17x hides MCP tools behind ToolSearch, so a model must search before it can call an agent's own tools; models behind custom endpoints may never do that. HoloDeck now sets ENABLE_TOOL_SEARCH=false unless the operator exports it.
    • More built-in Claude tools are blocked unless declared. NotebookEdit (writes files) now needs file_system.edit, and WebSearch needs web_search: true. Before, both were available to every agent. The block is session-wide, so a subagent that needs one of these tools still needs it declared at the top level.

    • Trace redaction works on OpenTelemetry SDK 1.45+ and covers current GenAI tool attributes. The SDK now freezes span attributes before on_end, which made RedactingSpanProcessor fail open with only a warning.     Fixed¶

    • ChromaDB search results came back worst-first. Chroma returns a cosine distance, which was used as the similarity score, so semantic results were ranked in reverse and min_similarity_score / min_score kept the least similar chunks. Scores are now 1 - distance, so the best match ranks first.
    • Dashboard skipped runs that used a code grader or a file-based skill. Loading a stored run re-validated its agent snapshot, which imported each type: code grader and read each skill's SKILL.md. Those live next to the agent, not the results, so holodeck test view dropped such runs (cannot import grader module, skill path is not a directory). Stored runs now load as snapshots and skip that work; agent.yaml loading still checks both before any agent call.
    • type: code graders now see tool invocations on single-turn test cases. The single-turn path ran evaluations before pairing tool calls with results, so GraderContext.tool_invocations was always empty and any grader that checked tool calls or results scored 0, even though the test result listed the invocations. Calls are now paired once and the same list goes to the grader, the expected-tool arg matcher, and the TestResult. Single-turn graders also receive test_case_name. Multi-turn (turns:) cases were not affected.
    • Code graders get their own copy of tool invocations. A grader that edited ctx.tool_invocations[i].args or .result changed the invocations saved in the TestResult and seen by later graders. Each grader context now holds deep copies.
